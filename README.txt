استودیوی بی‌نهایت — نسخه بازسازی‌شده از سایت مرجع
================================================

نسخه آنلاین GitHub Pages:
https://mahdiarmahdipour.github.io/binahayat-studio/

مرجع:
https://binahayat-studio.haian1048294.chatgpt.site/

این پروژه ۹ صفحه دارد: خانه، درباره ما، آثار، وبلاگ، همکاری و چهار صفحه آثار.
متن، ساختار و چیدمان از صفحات قابل مشاهده سایت مرجع بازسازی شده‌اند.
فونت‌ها، لوگوها و سه ویدئوی اسلایدر از فایل‌های ارائه‌شده توسط شما هستند.
تصاویر شوریل و سه شیت هویت بصری از فایل‌های عمومی خود سایت مرجع دریافت شده‌اند.
تم روشن و تاریک، خوانایی متن، لوگوی متناسب هر زمینه و منوی موبایل اصلاح شده‌اند.

اجرا
----
Node.js لازم است. پروژه هیچ وابستگی npm ندارد.
در پوشه پروژه اجرا کنید:

  node scripts/build.mjs
  node scripts/validate.mjs
  node server.mjs

سپس http://127.0.0.1:4173/ را باز کنید.
با Ctrl+C سرور متوقف می‌شود. برای تغییر پورت، متغیر PORT را تنظیم کنید.
فایل dist/index.html را مستقیم باز نکنید؛ مسیرهای سایت به یک سرور HTTP نیاز دارند.

ویرایش
------
src/pages/ : ساختار هر صفحه، بدون کدهای چارچوب و سرویس مرجع
src/styles/reference.css : چیدمان اصلی
src/styles/theme.css : فونت‌ها و اصلاحات تم و لوگو
src/app.js : تم ذخیره‌شونده، منو و اسلایدر
src/collaboration-form.js : ثبت فرم در همان صفحه و دریافت تأیید سرور
src/collaboration-config.js : آدرس عمومی برنامه گوگل و وضعیت فعال‌بودن فرم
apps-script/ : ذخیره خصوصی فایل Word در Drive و ارسال خودکار به ایمیل استودیو
content/pages.json : مسیرها و مشخصات صفحه‌ها
content/aparat-videos.json : ویدئوهای هر اثر، به تفکیک صفحه
dist/assets/ و dist/fonts/ : همه دارایی‌های سایت و فایل‌های ارائه‌شده
dist/ : خروجی آماده میزبانی در ریشه یک دامنه

پس از تغییر فایل‌های src یا content، دستور build را دوباره اجرا کنید.
برای آپارات، URL کامل https://www.aparat.com/v/شناسه یا لینک embed پشتیبانی می‌شود.
لینک‌های آپارات بر اساس فهرست تفکیک‌شده ارائه‌شده توسط شما تنظیم می‌شوند.
صفحات مستقل همبستگی و Egg Men حذف شده‌اند؛ ویدئوی همبستگی در جنگ رمضان قرار دارد.

موارد باقی‌مانده برای انتشار نهایی
--------------------------------
۱. هر ۱۵ ویدئو در چهار بخش بر اساس فهرست شما ثبت شده‌اند.
   شناسه irw8ct4 برای «دیوانه خانه اداره مهاجرت» جداگانه توسط شما تأیید شد.
۲. ۱۳ لینک وبلاگ در مرجع به # می‌روند؛ همان ساختار حفظ شده و مقاله‌ای ساخته نشده است.
۳. فرم همکاری فعال است؛ ثبت در همان صفحه و ذخیره فایل Word در Drive خصوصی آزمایش شده‌اند.
   ایمیل خروجی با پیوست Word به binahayatstudio.ai@gmail.com بررسی شده؛ تأیید دریافت در صندوق مقصد باقی است.
۴. انتشار سایت با GitHub Pages و workflow اختصاصی آن تنظیم شده است.

ارسال فرم همکاری
----------------
GitHub Pages میزبان استاتیک است. فرم با POST در یک iframe پنهان به Google Apps Script می‌رود؛
مخاطب وارد سایت دیگری نمی‌شود و نیاز به ورود به گوگل ندارد. پیام موفقیت فقط پس از تأیید
پردازش از سرور و تطبیق شناسه، nonce و مبدأ پاسخ نشان داده می‌شود، نه صرفاً بارگذاری iframe.
Word واقعی با پسوند DOCX در سرور ساخته و در پوشه خصوصی Drive ذخیره می‌شود؛ سپس همان فایل
ذخیره‌شده از Drive خوانده و به ایمیل ثابت استودیو پیوست می‌شود. پوشه و فایل‌ها عمومی نمی‌شوند.
این سند شامل نام، راه ارتباطی، نوع پروژه، بازه زمانی، شرح چندخطی درخواست، شناسه و تاریخ ثبت است.
اطلاعات فرم در GitHub یا localStorage ذخیره نمی‌شود و مخاطب نمی‌تواند گیرنده ایمیل را تغییر دهد.

وضعیت فعلی: مجوزهای گوگل و setupStudio کامل شده‌اند. نسخه ۱ برنامه وب با اجرای حساب مالک و
دسترسی دریافت فرم بدون ورود مخاطب منتشر شده و آدرس واقعی آن با enabled=true به سایت متصل است.
در آزمایش واقعی سایت، تأیید ثبت در همان صفحه دریافت شد و فایل DOCX ساخته‌شده در Drive خصوصی
ذخیره و در Google Docs باز شد. محتوای DOCX نیز با بررسی ZIP/XML و بازکردن با python-docx تأیید شد.
در بررسی ۲۰۲۶/۱۱/۰۳، ایمیل آزمایشی در بخش Sent حساب مالک با گیرنده درست و پیوست Word مطابق نسخه
Drive دیده شد. ارسال خروجی تأیید شده است؛ دریافت ایمیل و پیوست در صندوق مقصد هنوز نیاز به تأیید گیرنده دارد.
پوشه خصوصی بایگانی: https://drive.google.com/drive/folders/1m3dzVVgT5uCDoqd3BFjJD3aqXjSTyH_G
پروژه مالک: https://script.google.com/home/projects/19cEhp0Ynj9Yj6NxCQqVzY4HBKTiZWDp_offEjaXLu6WiB4rkpkbzdYU2/edit

راه‌اندازی مالک:
۱. در Google Apps Script یک پروژه با نام Binahayat Studio — Collaboration ایجاد کنید.
۲. محتوای apps-script/Code.gs و WordDocument.gs را در پروژه قرار دهید؛ می‌توان هر دو را در
   Code.gs یک‌جا چسباند. فایل appsscript.json را نیز دقیقاً مطابق پوشه apps-script تنظیم کنید.
۳. تابع setupStudio را یک‌بار با حساب مالک اجرا و مجوزهای گوگل را تأیید کنید. این تابع یک پوشه
   خصوصی می‌سازد و یک اجرای زمان‌بندی‌شده برای بررسی ایمیل‌های در انتظار، هر ۳۰ دقیقه، ایجاد می‌کند.
۴. Deploy > New deployment > Web app: Execute as = Me؛ Who has access = Anyone.
۵. آدرس واقعی /macros/s/.../exec را در src/collaboration-config.js بگذارید، enabled را true کنید
   و سایت را دوباره بسازید و منتشر کنید. سپس ثبت در همان صفحه، ذخیره فایل و دریافت ایمیل را آزمایش کنید.
نشانی /collaboration/?setup=email دیگر فعال‌سازی یا مسیر ارسال جداگانه‌ای ندارد.

مجوزها به فایل‌های ساخته‌شده توسط همین برنامه (drive.file)، ارسال ایمیل بدون خواندن صندوق،
اجرای زمان‌بندی‌شده و درخواست HTTP برای خواندن فایل از API خود گوگل محدود شده‌اند.
هیچ کلید، رمز SMTP یا توکن ایمیلی در کد عمومی قرار ندارد؛ توکن فقط هنگام اجرا در گوگل استفاده می‌شود.
حساب شخصی رایگان گوگل فعلاً سهمیه ۱۰۰ گیرنده ایمیل در ۲۴ ساعت دارد. برنامه سقف ۹۰ تلاش ایمیل و
۱۰۰ فایل در هر بازه ۲۴ ساعته می‌گذارد. درخواست ذخیره‌شده هنگام خطای ایمیل در صف باقی می‌ماند و
اجرای زمان‌بندی‌شده با فاصله بیشتر دوباره تلاش می‌کند. تکرار ارسال همان درخواست فایل تازه نمی‌سازد.
MailApp شناسه جلوگیری از تکرار ندارد؛ قطع اتصال پس از ارسال ممکن است اعلان ایمیل را با همان شناسه
درخواست تکرار کند، اما نسخه Drive همچنان یکی است. سهمیه‌ها و فضای Drive تابع محدودیت‌های گوگل‌اند:
https://developers.google.com/apps-script/guides/services/quotas

انتشار
------
GitHub Pages از بخش Settings > Pages با منبع GitHub Actions فعال شده است.
workflow در .github/workflows/pages.yml ابتدا سایت را می‌سازد و بررسی می‌کند، سپس
مسیرها را برای پیشوند مخزن تنظیم و پوشه dist را منتشر می‌کند.
تغییر فایل‌های src، content، scripts یا dist روی شاخه main انتشار تازه را آغاز می‌کند.
برای اجرای دستی، از Actions > Deploy Binahayat Studio to GitHub Pages > Run workflow استفاده کنید.
اسکریپت prepare-pages.mjs فقط خروجی انتشار را تغییر می‌دهد؛ فایل‌های src دست‌نخورده می‌مانند.

کل پوشه dist را در ریشه میزبان استاتیک قرار دهید. مسیرهای directory/index.html
باید پشتیبانی شوند. فایل .openai/hosting.json برای Sites تنظیم شده ولی project_id
ندارد؛ پس از فعال‌شدن Sites، یک بار ثبت Site و درج شناسه واقعی لازم است.
این پروژه هیچ شناسه Site، کلید، رمز یا توکن دسترسی ساختگی ندارد.
برای GitHub، پوشه پروژه شامل src، content، scripts و dist را کامل نگه دارید.
تمام فایل‌های ویدئو کمتر از محدودیت ۱۰۰ مگابایت هر فایل GitHub هستند.
فایل‌های فونت و برند، اقلام ارائه‌شده شما هستند؛ مجوزهای آن‌ها در این پروژه تغییر نکرده است.
